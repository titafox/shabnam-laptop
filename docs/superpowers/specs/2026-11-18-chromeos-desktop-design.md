# 开放桌面 v7：ChromeOS 风格桌面 设计文档

日期：2026-11-18
状态：用户 2026-11-18 指示「直接开工」，已实现，待推到真机

> **实现与本文的出入（以此为准）**
> - 源码在 `lan-helper/desktop-cros/`，不在 `lan-helper/desktop/`（后者当时有另一个会话在改）。控制通道的 `AgentService.java`、`ApkProvider.java` 构建时直接引用 `lan-helper/desktop/` 里的原件。
> - `versionCode` 用 100（`versionName` cros-1），不是 7：`desktop/` 里已经出现过一个 v7 包，取大值避免冲突。
> - §6 的兜底改为：全局未捕获异常处理器写入崩溃标记，下次启动进安全模式并把堆栈 POST 到 Mac 的 `/log`；装了新版本会自动退出安全模式。原文"界面崩了通道还在"是错的（同进程），实际是进程重启后安全模式重新拉起通道。
> - 应用变化时整表重查（有图标磁盘缓存，代价小），没有做增量更新。
> - 模拟器测试必须用 `TEST=1 ./build.sh` 打的 `TEST-ONLY.apk`（通道地址指向空地址）。正式包在模拟器里会连上真实控制通道并重放最后一条指令。

## 1. 意图

设备是中国移动云电脑 EC-NB01-CE（RK3568，Android 11，1920×1080 横屏，笔记本形态，有全键盘和鼠标指针，无 root）。用户要把它当一台**通用电脑**用，后续会交给星链代理商做日常办公。

现有桌面 `local.cloud.launcher` v6（`lan-helper/desktop/Main.java`）是代码拼出来的手机式应用网格，不好看，也没有针对键盘鼠标设计。用户要一个**更好看、非常快**的桌面，风格明确指定为 **ChromeOS**。

用户原话要点：「美观度什么的都需要更好」「美观度以及性能」「先不能做代理商的工具，而是作为一台电脑」「要搞成 chromeos 风格」「（底栏）只在桌面显示，先这样做」。

## 2. 目标、非目标、反目标

### 目标
- ChromeOS 式结构：干净壁纸、底栏（Shelf）、启动器面板、快捷设置面板。
- 键盘鼠标优先：打字即搜索、方向键导航、右键菜单、鼠标悬停反馈。
- 快：回到桌面立即可用，面板弹出不掉帧，内存占用小。
- 覆盖升级现有包 `local.cloud.launcher`，默认主屏设置不变。
- 控制通道（`AgentService`）功能和行为完全不变。

### 非目标（本次不做）
- 底栏在其他应用上方悬浮显示。
- 「正在运行的应用」指示、窗口管理、多窗口。
- 桌面上摆图标、小部件、通知面板。
- 代理商业务入口（续费、购买等）。
- 基础工具应用的选型和推送：这是紧接着的**另一个独立项目**，本桌面做完后单独讨论。
- Rust 或任何原生库。

### 反目标（出现即算失败）
- **控制通道断掉**。设备没有 ADB，通道是唯一的远程手段。
- **桌面启动即崩溃导致设备没有可用主屏**。见 §6 安全措施。
- 为了动效牺牲流畅度。宁可没有动画，也不要掉帧的动画。
- 使用 Google / ChromeOS 的标志、官方壁纸或官方图标。只借用布局和交互方式。

## 3. 约束

- 无 root：改不了系统状态栏和导航栏，只能画自己这一屏。
- 不能注入点击：安装升级包时用户必须在设备上点「安装」确认。
- 包名 `local.cloud.launcher`，签名钥匙 `lan-helper/.install-keys/apk-signing.pem`（CN=DeviceDiagnostics2），必须用它签，否则无法覆盖安装。`versionCode` 从 6 升到 7。
- `targetSdkVersion` 保持 30，`minSdkVersion` 保持 23。
- `AgentService.java`、`ApkProvider.java` 不改逻辑。`Main` 里与它们配合的行为必须保留：`onCreate` 和 `onResume` 启动服务；`AgentService.wantProjection && !hasProjection` 时发起投屏授权并把结果转交服务；未授予悬浮窗权限时给出入口。
- 不引入 AndroidX 或任何第三方库，只用系统框架控件。APK 保持小（目标 2MB 以内，主要是壁纸）。
- 构建工具在 `/opt/homebrew/share/android-commandlinetools/`（build-tools 34–37，platforms android-34 及以上）。仓库里目前**没有构建脚本**，现有 APK 是手工命令打的。
- 项目目录不是 git 仓库。

## 4. 做法比较

| | A. Rust 全权绘制 | B. Rust 内核 + 原生界面 | C. 纯原生（Java + 系统控件） |
|---|---|---|---|
| 流畅度上限 | 最高 | 同 C | 做对即满帧 |
| 冷启动 | 最慢（初始化渲染器） | 快 | 最快 |
| 内存与体积 | 多 10–20MB | 略增 | 最小 |
| 中文、输入法 | 全部自己处理 | 系统自带 | 系统自带 |
| 工作量 | 最大 | 中 | 最小 |

**用户选了 C**。理由：桌面的"快"主要来自少做事（缓存图标、不重复查询、不过度绘制），C 完全能做到；A 多买到的只是画面掌控力，代价是冷启动、内存和工作量。

布局上比较过任务栏式（Windows）、Dock 式（macOS）、搜索启动式三种，**用户指定 ChromeOS 风格**。

## 5. 设计

### 5.1 画面结构

```
┌────────────────────────────────────────────────────────────┐
│                                                            │
│                       壁纸（无图标）                        │
│  ┌─────────────────┐                     ┌──────────────┐  │
│  │ 搜索应用、网址… │                     │ Wi-Fi  蓝牙  │  │
│  │ 最近使用        │                     │ 深色   设置  │  │
│  │ ○ ○ ○ ○ ○       │                     │ 亮度 ━━━━━   │  │
│  │ 全部应用        │                     │ 音量 ━━━     │  │
│  │ ○ ○ ○ ○ ○       │                     │ 82% · 日期   │  │
│  │ ○ ○ ○ ○ ○       │                     └──────────────┘  │
│  └─────────────────┘                                       │
│ (◎)            ○  ○  ○  ○  ○  ○              ( ● ▮ 14:32 ) │
└────────────────────────────────────────────────────────────┘
  启动按钮        固定应用（居中）                 状态胶囊
```

两个面板不会同时打开；点面板外或按 Esc 关闭。

### 5.2 底栏（Shelf）
- 屏幕底部一条半透明深色栏，只在桌面可见。
- 左：圆形启动按钮。中：固定应用，居中排列。右：状态胶囊，显示通道状态点、网络、电量（有电池才显示）、时间。
- 固定应用点按启动；右键或长按出菜单：取消固定、应用信息。
- 默认固定：浏览器、文件管理、设置、F-Droid 中已安装的那些（由构建者按设备上实际包名确定）。固定列表存本地，可增删、可拖动排序属于可选项，不做也行。
- **不显示"正在运行"小横条**。样机里画了，但没有额外权限无法知道哪些应用在运行，本次去掉。（我的决定）

### 5.3 启动器面板
- 从左下角弹出的圆角面板，约占屏宽 36%、屏高 74%。
- 顶部搜索框，弹出即获得焦点。
- **在桌面上直接敲任何可打印字符，自动打开启动器并把字符填进搜索框。**（我的决定，这是最可靠的键盘入口）
- 键盘上的开始键（Meta）和搜索键：若系统把按键交给桌面就用来开关启动器；Android 可能自己截走 Meta 键，**需在真机验证**，不行就放弃，不影响上一条。
- 无搜索词时：「最近使用」一行（5 个）加「全部应用」网格（5 列，按名称排序，可滚动）。
- 有搜索词时：只显示匹配结果列表，第一项高亮，回车启动。
- 匹配规则：应用名包含、拼音全拼前缀、拼音首字母（如 `sz` 命中「设置」）。拼音用系统自带的 `android.icu.text.Transliterator`（Android 10 起可用），不带字库；低版本上退化为只匹配名称。（我的决定：这台机器是英文实体键盘，没有拼音匹配搜中文应用名会很别扭）
- 搜索词像网址（含点号且无空格，或以 `http` 开头）时，结果首项是「打开网址」，交给系统默认浏览器。
- 「最近使用」只记录**通过本桌面启动**的应用，按最近启动时间排，不申请使用情况权限。（我的决定）
- 方向键在网格里移动焦点，回车启动，Esc 关闭。
- 图标右键或长按菜单：固定到底栏 / 取消固定、应用信息、卸载（调系统卸载确认）、从启动器隐藏。
- 默认显示全部可启动应用（含移动定制应用）。被隐藏的应用可在「桌面设置」里恢复。（我的决定）

### 5.4 快捷设置面板
- 点状态胶囊从右下角弹出。
- 开关区：
  - **Wi-Fi**：显示当前状态；点按打开系统 Wi-Fi 面板（Android 10 起应用不能直接开关 Wi-Fi）。
  - **蓝牙**：设备有蓝牙才显示；能直接开关就直接开关，不能则跳系统蓝牙设置。
  - **深色 / 浅色**：切换桌面自身主题，立即生效并记住。
  - **设置**：打开系统设置。
- 滑块区：
  - **音量**：直接调媒体音量。
  - **亮度**：需要「修改系统设置」权限。未授权时滑块置灰，点按跳到授权页；设备不支持调亮度则隐藏。
- 底部：电量（有电池才显示）、日期、「桌面设置」入口、通道状态文字（如「控制通道：已连接 Mac ✓」）。未授予悬浮窗权限时这里显示警告并可点按去授权。
- **去掉样机里的「截图」开关**。现有截图是给 Mac 远程用的，本地截图保存是另一个功能，本次不做。（我的决定）

### 5.5 桌面设置（一个简单的页面或对话框）
- 换壁纸：内置 3–4 张自制壁纸（抽象渐变类，不用任何第三方或 Google 素材），外加「从文件选择图片」。选中的图片缩放到屏幕分辨率后存到应用私有目录。
- 恢复被隐藏的应用。
- 系统快捷入口，保留 v6 现有那 8 项里系统设置首页到不了的：应用管理、开发者选项、悬浮窗权限、默认桌面。
- 版本号和通道状态。

### 5.6 视觉
- 默认深色。面板底色近 `#202124`，强调色偏蓝（近 `#8AB4F8`），圆角大（面板约 20dp，开关胶囊全圆角）。浅色主题对应翻转。颜色集中定义成一组主题常量。
- **不做背景模糊**（RK3568 上代价高），用半透明纯色代替。
- 图标统一尺寸。自适应图标用圆形遮罩；旧式图标垫一个圆形浅色底板，使整体观感一致。（构建者可微调）
- 应用自身图标：需要新做一个（当前包没有图标），圆形、简单几何图形即可。
- 鼠标悬停和键盘焦点都有可见的高亮。
- 动效只用位移和透明度，时长 ≤150ms；面板弹出一个、关闭一个，仅此而已。

### 5.7 性能要求
- 主线程不做磁盘和网络读写、不做应用列表查询。
- 应用列表在后台线程加载；结果（包名、入口、名称、拼音键）缓存到本地，下次启动先用缓存画，再后台校对。
- 图标按显示尺寸转成位图并落盘缓存，键为包名加版本号；内存里用上限固定的缓存。
- 监听应用安装、卸载、更新广播，增量更新，不整表重查。
- 网格用系统自带的可回收列表控件，不一次性创建全部图标视图。
- 时钟每分钟刷新一次（对齐整分），不用 2 秒轮询。通道状态点在桌面可见时低频刷新。
- 壁纸解码一次，尺寸不超过屏幕分辨率。
- 无重叠的不透明大背景层，避免过度绘制。
- 验收参考值（真机上量，达不到要回报而不是硬凑）：从按主页键到桌面可交互无可感知延迟；启动器首次弹出 ≤200ms、之后 ≤1 帧开始动画；滚动全部应用不掉帧；桌面进程常驻内存相比 v6 增量 ≤30MB。

## 6. 安全措施（针对"没有可用主屏"）

设备没有 ADB，新桌面一旦启动崩溃，只能靠人在设备上操作恢复。因此：

1. `Main.onCreate` 第一件事仍是启动 `AgentService`，在任何新界面代码之前。这样即使界面崩了，通道也大概率已经起来，可以远程推修复包。
2. 新界面的构建整体包在异常捕获里。捕获到异常就退回**安全模式**：一个极简页面（等同 v6 的列表：系统设置入口加全部应用），并在通道日志里上报异常内容。
3. 不卸载设备上现有的其他主屏和引导包（`local.cloud.desktop`、`local.helper.diag2` 等），它们是最后的退路。
4. 推到真机之前，先在 Mac 本地的 Android 模拟器上跑通（本机装有 emulator 和 system-images；若没有 Android 11 镜像，用现有镜像验证不崩即可，并说明差异）。
5. v6 的 APK（`lan-helper/dist/launcher.apk`）先另存一份备份。注意：Android 不允许降级安装，所以真正的回滚方式是**再推一个版本号更高的修复包**，不是装回 v6。

## 7. 交付与验证

- 源码仍放 `lan-helper/desktop/`，新增资源目录。文件怎么拆由构建者定，但不要全堆在 `Main.java`。
- 新增 `lan-helper/desktop/build.sh`：一条命令完成编译、打包、对齐、签名，产出 APK。
- 推送：`ctl.py install <apk>` 或 `queue-apk.py`，**需要用户在设备上点「安装」**。推送前要先跟用户确认人在设备旁。
- 验证：模拟器跑通；真机上用 `ctl.py screenshot` 抓桌面、启动器、快捷设置三张图核对；`ctl.py inspect` 确认通道仍然响应；确认投屏截图功能在升级后仍可用（升级会杀掉服务进程，投屏授权需要用户重新点一次，这是预期行为）。
